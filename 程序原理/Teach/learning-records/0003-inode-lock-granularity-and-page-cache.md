# 深入理解 inode 锁的粒度和 Page Cache 工作机制

用户在第三课前的对话中提出了三个关键追问，展示了从"理解概念"到"推导设计结论"的跨越：

1. **"如果两个 mount 点指向同一目录，两个 CPU 会发起相同的 I/O 吗？"** — 用户自己推导出了 bind mount 场景下的并发问题。回答后，用户又追问**"锁的是 mnt 这个 inode 吗？路径越长锁的 inode 会越多？"** — 这触及了 inode 信号量真正的粒度（父目录 inode），以及锁的持有时间（一层解析完就释放，不积累）。

2. **"路径越长越容易冲突？但根目录才是最容易冲突的吧？"** — 用户自行发现了两个看似矛盾的直觉，然后理解了关键区分：dcache 命中时不锁，根 dentry 永不出缓存所以永不锁，真正的热点是"目录热度"（create/unlink 频率）而非"目录深度"。

3. **"目录深度决定了冷启动的 IO 次数，目录热度决定了多进程访问时的性能？"** — 用户自行总结出了文件系统性能分析的完整两轴框架，该框架已被纳入第三课的核心概念。

**Status: active**

**Implications**: 用户已经具备了独立推导内核设计推理的能力。教学可以更进一步——不再只是解释"是什么"，而是给出核心约束条件让用户自行推导设计结论。对 Page Cache 的理解也应该用类似的"先给框架，再问问题"的方式推进。
