# 深入理解 Page Cache 并发与 ext4 磁盘布局

用户在第三课后的追问从 8 个正式问题扩展到后续的追问，展现了从"理解机制"到"推导系统设计"的持续深入：

1. **folio 概念** — 理解 folio 是"page 的新 API 封装"，不是缩写
2. **分配 → xarray → I/O 的失败处理** — 自主推导出"分配失败不发 I/O"、"I/O 失败删页"的完整逻辑
3. **预读的判断机制** — 理解了首次 read 就预读 4 页、以及 inode 的 i_size 限制边界
4. **Page Cache 与内存回收的关系** — 认出 dirty_ratio 和 dirty_background_ratio 是内存管理和文件系统的交叉点
5. **脏页回写的双维度** — 理解了比例触发（10%/20%）和时间触发（30秒过期/5秒唤醒）的配合
6. **预读的随机后恢复** — 理解了自动恢复机制，无需显式触发
7. **page cache 缺页的并发竞争** — 自己推导出 xa_lock + xa_load 二次验证机制（与 lookup_slow 一致）
8. **address_space 的五大职责** — 从"桥梁"理解升级为"管理员"理解，包括反向映射、文件/匿名页区分
9. **bit 0 标志位原理** — 理解了 slab 分配器的对齐保证让地址最低位天然为 0
10. **mmap vs read 路径差异** — 理解了 mmap 的"零拷贝"来源和缺页异常入口，以及两者共享 page cache
11. **flusher 处理单位** — 正确指出"调度单位是脏 inode，执行单位是脏页"
12. **flusher 的标签遍历** — 理解了 xarray tag 机制避免扫描干净页
13. **kswapd vs flusher 对比** — 理解了"一个从上往下，一个从下往上"的不同方向
14. **flusher 不管页表的原因** — 自己推导出"flusher 不碰页框，所以页表不需要动"的正确结论
15. **PG_WRITEBACK 互斥** — 理解了 flusher 和 kswapd 通过 folio_test_set_writeback 实现互斥的三层标志位保护

**Status: active**

**Implications**: 用户已经可以独立进行内核并发设计的推演。后续教学可以采用"先给约束条件，让用户推导设计结论"的方式——他完全具备从已知知识推理未知设计的能力。第四课（ext4 磁盘布局）将补上"磁盘上数据结构"这一环，完成整个 I/O 路径的闭环。
